# `.context` — bbq-telestration 작업 컨텍스트

이 폴더는 **bbq-telestration (App)** 프로젝트의 작업 컨텍스트를 추적한다.
목적은 단 하나 — **다음 작업자(사람이든 AI든)가 멈춘 지점에서 바로 이어서 일하게** 하는 것.

> Mockingbird 의 모든 프로젝트(각 App·API, portal, root/projects 호스트)는 자기
> 디렉토리 안에 `.context/` 를 가진다. sparse pull/scaffold 시 프로젝트 트리째 따라오므로
> **각 작업자는 서로의 컨텍스트를 그대로 들고 간다.** 새 프로젝트는 이 `.context/`
> 템플릿이 복사되고 placeholder 토큰이 프로젝트명으로 자동 치환된다.

## 파일 구성

| 파일 | 성격 | 언제 쓰나 |
| ---- | ---- | --------- |
| `state.md` | **현재 상태 스냅샷** (덮어쓰기) | 작업 끝낼 때 "지금 어디까지 됐나"를 최신화 |
| `journal.md` | **세션 로그** (append-only) | 작업할 때마다 한 일·이유·다음 단계를 맨 위에 추가 |
| `decisions.md` | **결정 기록** (append, ADR) | 되돌리기 어려운/논쟁적 결정을 내릴 때 |
| `README.md` | 이 안내 (거의 불변) | — |

## ⚠️ 작업 이어가기 프로토콜 (필수 — 시작 시 read, 종료 시 write 둘 다)

**시작할 때 (read — 필수):** 먼저 읽고, **이전 작업의 방향성·결정과 동일한 방향으로** 이어간다.
1. `state.md` 로 현재 위치·미완성·알려진 이슈를 파악한다.
2. `journal.md` 최근 2~3개 엔트리로 직전 맥락과 "다음 단계"를 읽고, 거기서 이어 시작한다.
3. `decisions.md` 로 고정된 결정을 확인한다 — **재논의·역행 금지** (바꿔야 하면 새 엔트리로 "대체됨" 명시).

**끝낼 때 (write — 필수):** 코드 변경과 `.context` 갱신을 **같은 push(`/git/push`)에 함께** 올린다.
1. `journal.md` **맨 위**에 이번 세션 엔트리를 추가한다 (날짜·작업자·한 일·이유·다음 단계).
2. `state.md` 를 현재 사실에 맞게 갱신한다 (오래된 내용은 지운다).
3. 중요한 결정을 내렸다면 `decisions.md` 에 한 줄이라도 남긴다.

> sparse pull 폴더엔 `.git` 이 없고 쓰기는 서버 중계 `/git/push` 라 git hook 이 안 먹는다.
> 그래서 이 갱신은 **에이전트(사람/AI)가 지키는 필수 규칙**으로 강제된다.

> 원칙: **journal 은 쌓고, state 는 갱신한다.** journal 은 "왜 이렇게 됐나"의 히스토리,
> state 는 "지금 어떤가"의 단면. 둘이 어긋나면 코드 > journal > state 순으로 진실.
